# Task 17.1 — `store/sqlite`, alongside the other two

**Goal:** a third backend, `store/sqlite` on `modernc.org/sqlite`, passing every
shared suite — `RunLedger`, `RunDeposit`, `RunProduct`, `RunPayment`,
`RunLending`, `RunRaces`, `RunConcurrentTxRaces` — with `store/pg` and
`store/mem` still present and still green. Nothing is deleted.

`store/mem` and `store/pg` are the oracles, and this is the last task in which
both exist. 17.2 and 17.3 delete them.

**Design:** `docs/superpowers/specs/2026-08-03-sqlite-only-store-design.md`.
Where this plan and the spec disagree on a *decision*, the spec wins. Where they
disagree on a *number*, this plan measured it — see below.

## What was verified before this plan was written

The spec makes one thing a precondition: comments must survive into
`sqlite_master`, "verified first, in 17.1, before the translation is written",
because if they do not, the ruling reverses for real. Done, against
`modernc.org/sqlite v1.56.0` and not against the system CLI:

- **modernc compiles in SQLite 3.53.3.**
- **A comment inside a statement's parentheses survives verbatim** into
  `sqlite_master.sql` — leading lines and trailing on-the-column-line alike.
  Same for a `CREATE INDEX`'s column list.
- **A comment above a statement is dropped.** This half is not in the spec and
  is the sizing surprise; see the ruling below.
- **`_pragma=foreign_keys(1)` on the DSN holds** on a pooled connection, and an
  orphan `REFERENCES` is refused with extended code **787**
  (`SQLITE_CONSTRAINT_FOREIGNKEY`).

So the ruling holds and the translation may proceed.

## The ruling this task needs, and it is not in the spec

**612 comment lines. 595 of them sit at column 0** — above a statement, not
inside one — and those are exactly the ones SQLite drops. The spec frames the
translation as "42 `COMMENT ON COLUMN`s move inside the parentheses". The real
translation is that nearly every argument in the file has to move inside a
statement or leave the database.

That matters because of what the property is *for*. `CLAUDE.md` says the
reasoning is recorded "in the database, because a missing constraint is
invisible in a schema dump". The arguments doing that work are precisely the
top-level ones — `0001_init.sql:38` opens "A note on what is NOT here:
`UNIQUE (book_id, name)`" and runs twenty lines.

**The ruling: every argument about something the schema does NOT do moves inside
the statement it concerns.** An absent constraint's argument goes in the
parentheses of the table it is absent from; an index's reasoning goes in its
column list, which was verified to survive. What stays at column 0 is narrative
that belongs to no statement — the file header's conventions list — and the file
opens by saying which of its comments reach a schema dump and which do not, so
that the next person to add one knows where to put it.

Where an argument spans two tables, it goes in the one whose absent constraint
it is about, and the other names it. Duplicating it is how a fact ends up in
nine places, which is the process file's second mechanism.

## Global constraints

The constraints from Task 17.0's plan carry, unchanged and not restated here —
in particular: **this plan carries no comment text**, every measurement is
watched failing first, and a correction's explanation is verified as hard as the
correction. Read `docs/superpowers/plans/2026-08-06-task-17.0-the-races-become-a-suite.md`.

Specific to this task:

- **Three backends, every run.** `go test ./...` runs `store/mem` and now also
  `store/sqlite`; `TEST_DATABASE_URL=… go test ./...` adds `store/pg`. All three
  green. **This is the task's entire point** and the `TEST_DATABASE_URL` line
  expires the moment it lands.
- **Everything the connection needs rides in the DSN.** A post-`Open` `Exec`
  configures one pooled connection and then looks like it worked. Anything that
  cannot ride in the DSN is a finding, not a workaround.
- **The ephemeral store is `file:/<random>?vfs=memdb`**, not shared cache — see
  the spec's *The test store is `memdb`* ruling. The retained connection and the
  random name are still required. A named path is a file under WAL, which no
  in-memory database can be.
- **`Update` retries with jittered backoff, and the budget must exceed the
  longest write transaction.** A file lets a retry read past an uncommitted
  writer; `memdb` blocks it. A guard for the budget has to open a file.
- **A storetest assertion that has to move is a defect in the port** until proven
  otherwise. No accept-or-refuse decision changes.
- **Two of the nine races do not bite on one run.** `ConcurrentAdmissionsAgreeOn-
  OneCentralBank` and `ConcurrentMarkReversedOnlyOneWins` each passed one run and
  failed within ten on `store/pg` with their guard removed. A single green run
  of either against `store/sqlite` is not evidence. Run them at `-count=10` when
  establishing anything about them.

## 17.1a — the driver, the DSN, and the two guards — DONE (`0ef06bc`, `127ac30`)

- [x] `store/sqlite/sqlite.go`: `Store` over `database/sql`. `Open(ctx, path,
      clock)`, empty path meaning ephemeral. `Close` idempotent.
- [x] DSN carries `_pragma=foreign_keys(1)`, `_pragma=busy_timeout(5000)` and,
      for the file case, `_pragma=journal_mode(WAL)`.
- [x] The ephemeral case retains one connection for the store's lifetime;
      `SetMaxOpenConns`/`SetMaxIdleConns` are set deliberately. **8 for a caller,
      +1 for the retained connection** — set equal and the last caller waits for
      a connection that never returns, which is a hang rather than an error.
- [x] `ErrReadOnly` and `ErrNestedTransaction`.
- [x] **Foreign keys are enforced**, and one more guard the plan did not ask for:
      the pragma reaches *every* pooled connection, not just the first.
- [x] **At most one non-primary-key unique index**, read from `sqlite_master`.
      Becomes an equality on `transactions_idempotency_key_idx` at 17.1b.
- [x] **Comments reach `sqlite_master`** — a test, because the property is now a
      convention about where a comment sits rather than something `COMMENT ON`
      gives for free.
- [x] **The retry, its backoff, and the budget**, with two tests: one on the
      ephemeral store pinning that a retry happens, one on a **file** pinning the
      delay and its size. The second's first draft ran on `memdb`, passed with
      the old budget and pinned nothing.

**Arguments the docs must make:** why every pragma rides in the DSN; why the
ephemeral database is `memdb` and named with a leading `/` rather than
`:memory:` or shared cache; what the connection-count choice costs and buys; why
the budget has a size rather than just a bound.

**Watch it fail:** drop `foreign_keys(1)` from the DSN and watch only the
foreign-key test fail — the point is that nothing else does. Add a second unique
index and watch the `sqlite_master` guard fail.

## 17.1b — the schema, translated whole

`store/sqlite/schema/0001_init.sql`, from `store/pg/schema/0001_init.sql`. The
arguments carry; the spellings do not.

- [ ] **`STRICT` on every table.** The vocabulary narrows to `INT`, `INTEGER`,
      `REAL`, `TEXT`, `BLOB`, `ANY`; what `BIGINT`, `SMALLINT`, `TIMESTAMPTZ` and
      `JSONB` were *saying* moves into comments and `CHECK`s.
- [ ] **Times become `TEXT`**: RFC3339, UTC, fixed fractional digits. The
      normalisation is load-bearing — mixed offsets or variable precision and
      lexicographic ordering silently stops being chronological ordering in
      listings. Nullability unchanged; SQLite sorts NULL first in `ASC`, which is
      what the existing convention wants.
- [ ] **`JSONB` becomes `TEXT CHECK (json_valid(col))`** — a constraint
      `store/mem` could never hold, and the first place dropping it buys
      something.
- [ ] **`BIGSERIAL` becomes an explicit `seq`**, `MAX(seq)+1` on insert.
      `AUTOINCREMENT` needs an `INTEGER PRIMARY KEY` and `seq` is not the key —
      book-scoped tables are keyed `(book_id, id)`. This puts `seq` under the
      rule README already states for every other counter, and makes it gap-free.
- [ ] The 3 partial indexes and the 1 unique index port unchanged.
- [ ] **Every argument moves inside a statement**, per the ruling above. The 42
      `COMMENT ON COLUMN`s and the 595 top-level lines are one job, not two.
- [ ] The file header states which of its comments reach `sqlite_master` and
      which do not.

**Verification for this step specifically:** dump `.schema` from a migrated
database and diff the *arguments* against `0001_init.sql`. An argument present in
Postgres and absent from the dump is the defect this whole step exists to
prevent. Report which arguments you checked, not which patterns you grepped.

## 17.1c — `migrate.go` and the store methods

- [ ] `migrate.go` ports with its applied-set table, `go:embed`ded `.sql` in
      filename order, one transaction each, and the limitation it documents about
      keying on filename with no checksum. **The advisory lock goes**, with no
      SQLite equivalent and none needed: one writer.
- [ ] `tx_*.go` port from `store/pg`'s, statement for statement.
- [ ] **`inSavepoint` goes, and it is one call site.** SQLite does not abort a
      transaction on a constraint violation — the statement rolls back and the
      transaction survives, so the cost the rule was equalising is not charged
      here. Delete the helper and its call.
- [ ] `pgx.ErrNoRows` → `sql.ErrNoRows`, about ten sites.
- [ ] `isUniqueViolationOn(err, "transactions_idempotency_key_idx")` has no
      direct port and needs none: SQLite names no index in its error, but
      `SQLITE_CONSTRAINT_UNIQUE` (2067) identifies it alone, given 17.1a's guard.
      A primary-key conflict is 1555 and is a different answer.
- [ ] `isTransient`'s `40001`/`40P01` become `SQLITE_BUSY`/`SQLITE_LOCKED`.

**Arguments the docs must make:** why 2067 alone is as targeted as matching an
index name, and what the `sqlite_master` guard is protecting; why the advisory
lock has no successor.

## The question Task 17.0 left, answered before this plan was executed

`assertOneWinner` requires every loser to fail with a **domain sentinel**.
Measured, on `modernc.org/sqlite v1.56.0`, in both configurations this task
uses — two transactions opened, both reading a balance, both writing:

| configuration | both open at once? | loser's error | code |
|---|---|---|---|
| `mode=memory&cache=shared` | **yes** | `database table is locked: database is deadlocked` | **6** (`SQLITE_LOCKED`) |
| file + `journal_mode(WAL)` | **yes** | `database is locked` | **5** (`SQLITE_BUSY`) |

Three things follow, and only the first was expected.

**SQLite meets `RunConcurrentTxRaces`' precondition.** Two write transactions are
open simultaneously in both configurations, the barrier releases, and the suite
is runnable. The five primitive races have a home after 17.2. That was the
outcome that would have changed 17.2 and it is ruled out.

**`busy_timeout` does not absorb this, and the spec says it mostly does.** Both
failures returned **immediately** — the whole probe ran in under 10ms with
`busy_timeout(5000)` set. That is correct SQLite behaviour rather than a
misconfiguration: a transaction that already holds a read and needs to upgrade
can never succeed by waiting, because the holder is blocked on it, so SQLite
declines to sleep and returns at once. **The spec's "mostly absorbed by
`busy_timeout`" is false**, and it is listed there under "mechanical, and nothing
to decide". It is neither.

**So `Update` must retry the unit of work**, on both 5 and 6. This is not a
workaround: it is what `store/pg`'s `isTransient` arm already does for
`40001`/`40P01`, and it is what makes the domain guard correct rather than
incidental. Today the money outcome is already right — one winner, balance 400 —
but by a lock refusal, not by `ErrInsufficientBalance`. A caller catching the
sentinel would not catch a busy error, and `assertOneWinner` fails on the reason
rather than the count.

**This is a behaviour decision and it belongs in the spec as a dated ruling**
before 17.1c is written — the repository's convention is that a reversed ruling
which reads like an oversight is worse than the original. Draft it as: the
`SAVEPOINT`-per-sentinel rule goes, as the spec says, but the cost it was
equalising reappears one level up, and what pays it is a retry rather than a
savepoint.
